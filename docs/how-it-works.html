aify-project-graph · v0.1.0

A code map your AI agent can trust.

It reads your codebase into a graph, then layers in a C++ compiler's ground truth on top — and exposes both to coding agents (Claude Code, Hermes, Codex) as a small set of MCP tools plus a live dashboard.

Built C++-first for game engines (Sand Castle, Echoes of the Fallen / Tesseract), it merges proven ideas from four similar open-source projects into one coherent system. The whole point: an agent should never be told "no callers / safe to delete" unless that's actually proven.

1What is it, in one minute

Coding agents are great at writing code but bad at knowing a large codebase — they grep, read the wrong file, and worst of all they hallucinate ("just delete foo(), nothing calls it" — when something does). This project gives the agent a reliable map and, crucially, tells it how much to trust each answer.

🗺️ A graph of your code

Every file, function, class, call, import, and inheritance edge — extracted with tree-sitter across many languages. Always available, instant, no toolchain needed.

🎯 Compiler ground truth

For C++, it drives clangd (the real compiler's language server) to resolve who actually calls a function across files — and marks those edges [lsp✓] as verified.

🛡️ An honesty contract

Every answer says where it came from. A "no callers" result is only trustworthy when it's proven exhaustive; otherwise the tool says so out loud.

2How it works — the layered architecture

Think of it as an escalation ladder. The bottom is always-on and cheap; each layer up adds precision where it matters. Everything writes into one graph, so a static query and a compiler-verified query live side by side.

🧩 Static graph  — always on
Tree-sitter parses every source file into nodes (File, Function, Method, Class…) and edges (CALLS, IMPORTS, EXTENDS…). Honors .gitignore; handles unity builds, monorepos, non-ASCII paths. This is the map.

3The trust model — the heart of it

Every edge carries a provenance tag, and every answer carries a trust banner. This is what separates this tool from "a graph with features": the agent always knows whether it can act on an answer or must verify first.

LSP_VERIFIED  [lsp✓]
clangd resolved it. Cross-file ground truth. "Don't re-grep this."
trust it
EXTRACTED
Tree-sitter saw it directly in the source. Exact, but single-file scope.
solid
INFERRED
A heuristic guess — e.g. a synthesized virtual-override edge. Useful lead, confirm before acting.
verify
AMBIGUOUS
Name matched several candidates. Surfaced for review, not silently dropped.
review
The one rule that defines the product: a tool may only claim "no callers / safe to delete" when it has proven exhaustive evidence (a ready clangd index that actually resolved that symbol). Otherwise it must say "absence is from the heuristic graph and is NOT exhaustive — verify with code_intel_references / rg."  Live testing on the real games caught two places where this slipped; both are fixed and regression-tested. A stale index or an unbuilt overlay also announces itself loudly, so "not found" never gets misread as "doesn't exist."

4What's borrowed from what — and how it's used

This isn't built from scratch, and it isn't a copy-paste of any one tool. Four mature projects each solved part of the problem well; this merges their ideas into one coherent system. Three are MIT (reused with attribution; reimplemented in our JS+SQLite shapes). One is unlicensed — patterns only, no code copied.

CG

codegraph

MIT · TypeScript · the static-graph & agent-UX donor
  • C++ resolution heuristics — receiver-type inference (obj->method() → the declared type's method), out-of-line Foo::bar matching, include-dir discovery.
  • Adaptive output — size the answer to the question, skeletonize redundant siblings instead of truncating.
  • Generated-file down-ranking — protobuf/moc/*_generated.h rank last so a hand-written symbol wins.
  • graph_trace / graph_explore — from→to call paths with inlined bodies; multi-symbol source bundles. "Treat this as already Read."
  • The "low-salience wall" doctrine — agents under-pick from big tool lists; enrich the verbs they already call rather than adding names. Shaped our whole tool-surface design.
  • MCP initialize server-instructions — the one channel that reaches every host's prompt.
Reimplemented in JS (their TS type-shapes differ). The trace/explore verbs and the gating philosophy are the biggest lifts.
GF

graphify

MIT · Python · the analysis & "self-describing" donor
  • Token-budgeted digest — our graph_digest: the whole project's analytic value (layers, hotspots, cycles, provenance) in ~1–2k tokens. Ends the "dashboard is an island" problem.
  • God-nodes / communities / cycles — the analytics behind graph_hotspots, graph_overview, graph_cycles.
  • Analysis-as-a-verb pattern — the same shared module backs both the agent verbs and the dashboard, so they never drift.
  • Safety hardening — sanitize_label against prompt-injection through indexed source; pre-parse file-size caps; SSRF guards.
  • IDF search ranking — rare identifiers outrank common ones.
Pure graph algorithms — ported cleanly. The "give the agent the dashboard's value as text" idea is graphify's signature contribution here.
UA

understand-anything

MIT · JS/TS · the import-resolution & dashboard donor
  • Import-map resolution — tsconfig path-aliases (@/foo) + extension probing, including the load-bearing leading-./ normalization.
  • Dashboard overview→drill-in — show ~8–30 cluster boxes, not 13k nodes; expand one cluster on demand. The legibility idea behind our new overview view.
  • Change-explain — our graph_explain_diff: keyed on a git diff → changed → affected → risk (the reverse of "what breaks if I touch X").
  • Non-ASCII enumeration & structural fingerprints — git ls-files -z; body-vs-signature change classification.
Its actual web dashboard (React-Flow + ELK) is the visual north star; we adopted its aggregation ideas onto our existing viz.
ACI

agent-code-intel

UNLICENSED · patterns only — no code copied
  • The evidence / exhaustiveness contract — the crown jewel: a references result reports {ready, degraded, cause, exhaustive, confidence} + warnings. "Definition-only ≠ no callers." This is the source of our whole honesty model.
  • LSP runtime & freshness — prewarm cold indexes, gate every answer on freshness, the resolveServer precedence chain.
  • Multi-runtime shim — one core behind MCP / CLI shims, so it runs on Claude Code and Hermes identically.
Internal/unlicensed, so every pattern was re-expressed from scratch ("reference parity," not copied code). Conceptually the most important donor: the trust contract is the product.

5How an agent actually uses it

A typical "I'm about to change this C++ function" flow. Notice it escalates from cheap-and-static to verified-and-precise, and stops the moment it has a trustworthy answer.

Orient — graph_digest for the lay of the land (subsystems, hot-spots, cycles), or graph_packet for one feature/symbol. ~1–2k tokens, no compiler needed.
Locate — graph_search / graph_whereis to find the symbol. If the index is stale it says so, so "not found" is never mistaken for "doesn't exist."
Get ground truth — graph_collect_code_intel warms clangd on the relevant files, turning callers into LSP_VERIFIED edges. First run is slow then cached; returns a compact summary, not a data dump.
Verify — graph_callers now shows [lsp✓] callers with a TRUST banner; code_intel_hierarchy walks the transitive call/override tree. An empty result is honestly labeled, never a false "safe to delete."
Understand the change — graph_trace from→to inlines the call path; graph_explore bundles several symbols' source; graph_explain_diff scores the blast radius of a diff. Source comes back "already-Read," so the agent stops opening files.

6The dashboard

A live HTTP view of the same graph the agents query — for humans who want to see the codebase. Launch it with the graph_dashboard verb (or it may already be running at http://127.0.0.1:7700).

Overview → drill-in

Starts as a handful of cluster boxes (communities / architecture layers), not thousands of nodes. Click a cluster to expand only it.

Provenance ribbon

Compiler-verified call edges render solid-green; heuristic ones dashed. A top-line "% LSP-verified" tells you how much of the call graph is ground truth.

Shader-binding map

For game engines: the CPU↔GPU seam — which C++ descriptor-write populates which GLSL buffer slot. No generic tool shows this.

Blast-radius

Select a symbol → everything it reaches lights up (changed = red, affected = amber), the rest fades.

Pathfinder + hotspots

Shortest path between two symbols; an idle panel of the highest-degree "god nodes" (the risky core).

2D / 3D / layers

Cytoscape 2D, a stacked-layer 3D view, and the code+feature+task multilayer overlay.

Note: the dashboard is an upgraded version of the project's existing graph viz (Cytoscape + 3d-force-graph). The analysis behind it — clusters, hotspots, provenance, shader map — is the same shared module the agents use, so the picture and the agent answers always agree.
