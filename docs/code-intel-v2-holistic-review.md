# Code-Intel v2 — holistic cohesion review (2026-05-08)

_3-reviewer panel + Hermes TL. Verdict: the trust-spine CORE is genuinely one coherent, differentiated system; but it is NOT "done" — one thesis-critical data-loss bug, ungated absence claims, and accreted-surface cohesion debt. "With fixes: yes."_

## R1 — Correctness / trust (MUST fix; thesis-critical)
- **C1 (CRITICAL, empirically confirmed) — edge data-loss on re-collect.** `importer.js` `upsertLspEdge`/`LSP_EDGE_OVERRIDE_SQL` promotes a pre-existing EXTRACTED/INFERRED CALLS edge to `LSP_VERIFIED` **in place**. Next collect runs blanket `DELETE FROM edges WHERE provenance='LSP_VERIFIED'` (importer.js ~408) and only re-creates edges clangd re-reports this run. If clangd doesn't re-report it (index-not-ready, budget-skipped, bounded, file dropped from compile DB) the original heuristic edge is **gone forever** (tree-sitter edges are only made at graph_index, not at collect). → `graph_callers` returns "NO CALLERS" for a symbol that has callers. **Fix:** don't mutate the heuristic edge in place — insert LSP edges as distinct rows OR record original provenance and restore on invalidation; invalidation deletes only edges this synthesizer created.
- **I2 — partial/budget-exhausted collects still run full invalidation+import.** A cold 3/200-file run wipes the entire prior verified set. **Fix:** gate invalidation on `status==='ok'` (or scope to files re-collected this run). Pairs with C1.
- **I1 — absence claims NOT gated on exhaustive evidence.** `callers.js:62,77`, `callees.js:76,103`, `neighbors.js:42`, `impact.js:72` return "NO CALLERS/…" **before** `buildTrustLine`. The most dangerous output has no provenance/verify hint. `code_intel_hierarchy` does it right. **Fix:** route empty-result returns through `buildTrustLine` (heuristic path appends "absence is NOT exhaustive; verify with rg / run graph_collect_code_intel"). Add cross-verb tests asserting this — currently untested.
- **I3 — `[lsp✓]` stamped on every hierarchy node even in bounded/not-ready mode** (`code_intel_hierarchy.js:268`), contradicting its own `lsp-partial` banner. **Fix:** gate per-node `[lsp✓]` on `indexReady===true`; add the missing assertion.

## R2 — Cohesion (make it read as ONE system; user's explicit ask)
- **Single taxonomy registry** `storage/taxonomy.js` (NODE_TYPES, RELATIONS + families CALL/IMPORT/INHERITANCE/BRIDGE, EDGE_PROVENANCE_TYPES). Highest-leverage cohesion fix.
- **`graph_neighbors` ALL_RELATIONS missing** OVERRIDDEN_BY/LOADS_SHADER/DECLARES_BINDING/HAS_DIAGNOSTIC → the new layers are invisible to the general neighborhood verb.
- **Phantom `Struct` node type** — consumers filter on it (importer ENCLOSING_TYPES, hierarchy RESOLVE_TYPES) but no extractor emits it (struct→Class). Drop from filters.
- **Three competing trust vocabularies** — `change_plan`/`preflight` say `TRUST STRONG/OK/WEAK` (edge-count axis), but the doctrine + lean default trains the agent on `lsp-verified/partial/heuristic`. Unify on the lsp axis as headline; edge-count secondary.
- **Mixed output contracts** — JSON (consequences/pull/find/explain_diff/hierarchy) vs text (callers/trace/explore/…) vs text+appended JSON (overview/hotspots/cycles, which also escapes the staleness wrapper). Document one rule or a uniform envelope; route analytics hybrid through the staleness wrapper.
- **Verb-surface over-accretion (37 in `full`, the default)** vs low-salience-wall doctrine. Collapse planning cluster (packet+consequences primary; hide/merge change_plan+preflight — they share computeDecision); retire dead locator aliases (lookup/summary already hidden — strip their back-references from visible descriptions); cross-link traversal verbs → "for transitive+exhaustive use code_intel_hierarchy"; introduce a default profile (~12-15) below `full`, gate analytics/long-tail.
- **EDGE_PROVENANCE_TYPES declared but unenforced**; `ShaderBinding` overloaded for glsl bindings + cpp descriptor-write stash (inflates analytics count) → distinct type or language-scope the count.
- **Possibly-dead advice** — "confirm overrides with code_intel_hierarchy kind=subtypes" passing a METHOD name → typeHierarchy on a method usually returns empty. Validate; if dead, advise call-hierarchy on the virtual or hierarchy on the owning class. Update server-instructions + the 3 verbs that repeat it.
