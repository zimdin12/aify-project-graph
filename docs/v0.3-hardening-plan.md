# v0.3 Hardening Plan

Status: **v0.3.0 is tagged but must NOT be called "stable for completeness queries."**
Source of truth for what ships in v0.3.x. Written 2026-07-26 after the Sand Castle
field test.

---

## The headline

A scored field test on the real sand_castle repo found `code_intel_references`
returning **3 of 8 call sites** while reporting:

```json
{ "exhaustive": true, "degraded": false, "confidence": "high", "warnings": [] }
```

That is a **false-confidence defect**, and it is the single worst failure this
project can have. Our own server instructions tell agents that
`evidence.exhaustive` is the source of truth and that `exhaustive:true` licenses
"no callers / dead code / safe to delete." The flag lied. An agent obeying our
documented contract would confidently ship the wrong answer — which is **worse
than shipping no tool at all**, because grep gets it right in one second.

sc-manager independently made the same mistake by hand (published "three call
sites" in two commits; the compiler found eight). **The tool would have confirmed
the wrong answer.**

### Ground truth (verified directly in the source)

`sim/terrain/Terrain.cpp` — 9 occurrences of `sample_fluid_drag`:
1 definition (:796) + 8 call sites (:1715, :3528, :3633, :3776, :5836, :5938, :6142, :6175).

| Tool | Returned | Correct |
|---|---|---|
| `code_intel_references` | 3 (:3633, :5836, :5938) | **3/8 — and claimed exhaustive** |
| `graph_whereis(expand)` | 3 (:1715, :3528, :5836) | 3/8 |
| `graph_callers` / `graph_impact` | 3 (:1676, :3354, :5102) | **0/8 — not call sites at all** |
| `code_intel_hierarchy` | 0 | 0/8 (correctly self-labelled untrustworthy) |

Union of every tool: **5 of 8**. Sites :3776, :6142, :6175 are invisible to the
entire toolset.

**Hypothesis checked and REJECTED:** these are not `#ifdef`-guarded. All 8 call
sites are plain runtime `if` statements in one file. So this is not conditional
compilation — clangd genuinely returned 3 of 8 within a single translation unit.

## P0 — the trust contract (blocks any "stable" claim)

### P0-1. `exhaustive:true` fails OPEN on unknown coverage — **the root cause**

`mcp/stdio/query/verbs/code_intel_live.js:111-133`. The grant is:

```js
if (freshness === 'fresh' && callsiteCount > 0 && coverage && coverage.complete === false) {
  return { exhaustive: false, ... };   // downgrade
}
...
if (freshness === 'fresh' && callsiteCount > 0) {
  return { exhaustive: true, confidence: 'high', ... };   // ← fires otherwise
}
```

The comment at :110 states the defect outright:

> `(coverage may be undefined for non-cpp / callers that don't pass it -> treated as trustworthy.)`

**Unknown coverage is treated as complete coverage.** The most safety-critical
flag in the system defaults to the unsafe value. Any path where `coverage` is
undefined, null, or where the probe failed to determine an answer lands on
`exhaustive: true`.

**Fix — invert the default to fail CLOSED.** `exhaustive:true` must require
*positive* proof of coverage, not absence of disproof:

- `coverage === undefined` / probe failed / non-cpp without an equivalent
  guarantee → `exhaustive: false`, `cause: 'coverage_unknown'`.
- Keep `exhaustive:true` only for `freshness==='fresh' && callsiteCount>0 &&
  coverage?.complete === true`.
- Same audit for `buildDefinitionsEvidence` (:167) — it grants `exhaustive:true`
  on `fresh && defCount>0` with **no coverage input at all**.

This is a deliberate behavior change: more `exhaustive:false`. That is correct.
Per the prior bias we already adopted: prefer a false "verify this" over a false
"complete."

### P0-2. Per-query index-coverage signal

`graph_health` reported `refsNotFoundSymbols: 2274` against `refsFoundSymbols:
6643` — **25% of symbols resolved no references at all**. That is a loud
partial-index signal that never reaches the per-query evidence.

- Never emit `exhaustive:true` while the session's unresolved-symbol ratio is
  non-trivial; carry the ratio into `evidence` so the agent sees it.
- sc-manager's phrasing, adopted: *"`exhaustive: true` must never be emitted when
  `refsNotFoundSymbols` is non-zero for the query."*

### P0-3. `graph_callers` reports the caller's declaration line as if it were the call site

`mcp/stdio/query/verbs/callers.js:82` writes:

```js
source_file: e.from_file, source_line: e.from_line,
```

…into fields the renderer prints as `EDGE A→B CALLS file:line`
(`mcp/stdio/query/renderer.js:51,60`). So the printed line is the **caller
function's declaration**, not the call site — while the format implies a call
site. That is why `graph_callers` scored 0/8: its three lines (:1676, :3354,
:5102) are function starts.

Function-granular edges are a documented design choice
(`docs/known-limitations.md`), and that is fine. **Presenting a declaration line
in a field that reads as a call site is not.** Fix one of:
- render as `CALLS (caller declared at file:line)`, or
- carry the real call-site line on the edge and print it.

The design limit is acceptable; the mislabeling is not.

### P0-4. Surface code-intel collection staleness in the *response*

The collection was `collectedAt: 2026-06-19` / `indexedCommit: 900915d5` while
HEAD was `f60c658` — **5 weeks and 100+ commits stale** — and this was only
visible deep inside `graph_health`. `graph_index` does **not** refresh it;
`graph_collect_code_intel` is a separate step nothing prompted.

- Put collection age/commit-drift into the `code_intel_*` and `graph_callers`
  responses, not just health.
- `lsp-evidence.js:210` already computes staleness and appends `— STALE,
  re-collect` to the *banner text*; that must also force `exhaustive:false` in
  the **structured** flag. Banner and flag disagreeing is exactly what our own
  instructions warn about — and the flag is the one we told agents to trust.

### P0-5. Re-run the scored test as a regression gate

The field test is a better oracle than anything in our suite. Encode it: a fixture
with a known call-site census, asserting we never report `exhaustive:true` with an
incomplete set. Ties into the borrow item "graph equivalence oracle" (P2-6).

## P1 — team enablement (why 3 of 5 teammates could not use it for 2 weeks)

### P1-1. Task #97 — hermes `platform_toolsets`: our docs left them stuck

sc-tester, sc-coder, sc-architect (hermes) cannot reach the graph. It sat
unactioned for **two weeks**. Reading the exchange honestly, **our documentation
caused the stall**:

- Their `~/.hermes/config.yaml` has `mcp_servers.aify-project-graph` registered
  but **no `platform_toolsets` section at all**.
- After `9d0192e`, our install doc says: if no allowlist exists, do **not** create
  one — look elsewhere.
- So we handed them a conditional with **no way to decide which branch applies**,
  and no verification step. Correctly cautious, and completely unactionable. They
  did the rational thing: nothing.

**This is a docs defect, not a user error.** Two concrete fixes:

1. **Give a decision procedure, not a conditional.** Add a verification step that
   *observes* whether the toolset is exposed (list tools in a live hermes session)
   so the branch resolves from evidence instead of guesswork.
2. **Reconsider the "never create it" guidance.** The codegraph reference
   installer (`reference/codegraph/src/installer/targets/hermes.ts:313-318`)
   **does** create the section when absent, seeding it with
   `[hermes-cli, mcp-codegraph]`. That is a mature, widely-installed tool treating
   create-if-absent as the working recipe. My caution was reasonable but may be
   over-conservative.

   Safe procedure to document: back up `config.yaml` → add `platform_toolsets.cli`
   containing the **known defaults plus** `mcp-aify-project-graph` → restart →
   verify graph tools appear **and** previously-working tools still do → revert
   from backup if anything regressed. That is reversible and decidable.

### P1-2. Correct the "each agent needs their own index" belief

sc-manager: *".aify-graph/ is gitignored, so it's per-machine — each agent needs
their own index, which nobody has built."*

**Likely false for their setup, and worth correcting because it reads as a
blocker.** `.aify-graph/` is per-**working-directory**, not per-agent. Agents on
the same machine pointed at `C:/Users/Administrator/sand_castle` all share the one
index sc-manager already rebuilt. Gitignore only matters across machines/clones.

Separate agents need separate indexes **only** if they use separate clones or git
worktrees. Verify which applies, then either tell them they already have it, or
document the worktree case explicitly. Either way this should stop blocking anyone.

### P1-3. `graph_index` silently leaves the overlay and code-intel stale

On sand_castle right now:
- `functionality.json` — **54 days old** (the overlay that makes plan briefs useful)
- `tasks.json` — **85 days old**, 9 tasks, **0 linked**
- code-intel collection — **5 weeks old**

`graph_index` refreshes the structural graph and briefs, and says nothing about
the other three going stale. Agents reasonably assume "reindexed" means current.
Add per-artifact age to health/index output with the specific refresh command for
each. `overlayQuality` already reports `tasksTotal: 9, linkedTasks: 0` — surface
that as an actionable line, not a buried metric.

### P1-4. Disk: superseded collection artifacts are not reaped

`sand_castle/.aify-graph/` holds **~450MB** of `code-intel-ci-*.json` — including a
single 353MB file from 2026-06-02 — plus an 864MB `graph.sqlite`. We added
`pruneSupersededCollections` for DB rows and `scripts/compact-graph.mjs`, but the
on-disk JSON envelopes accumulate. Reap superseded ones on successful collect.

## P2 — borrow backlog (from the 2026-07-26 reference re-pull)

Licenses: understand-anything **MIT**, codegraph **MIT**, graphify **Apache-2.0** —
all borrowable with attribution (`ATTRIBUTION.md` exists). agent-code-intel remains
pattern-only/UNLICENSED.

Ordered by how directly each attacks the P0 failure class.

1. **Turn `exhaustive:false` into a pointer, not a warning** (M). codegraph's
   thesis: *"the answer to 'how does A reach B' when no static path exists IS the
   dispatch site."* We built the honesty half. Surface the dispatch site + form +
   key + candidate targets whenever `exhaustive:false`. Our
   `dynamic-boundaries.js` (165 lines, 7 forms) is imported by exactly **one**
   verb (`trace.js`) — wire it into `graph_callers` / `code_intel_references` /
   `graph_consequences`. Add missing forms: `ruby-send`, `php-dynamic`,
   `reflection`, `var-key-dispatch`, `selector`.
2. **C++ macro pre-parse "blanking"** (M) — *verified gap: we have none.*
   `mcp/stdio/ingest/languages/cpp.js` is 383 lines with zero macro handling. A
   class with many reflection macros collapses to an ERROR node and **the class,
   its bases, and all members vanish**; `FORCEINLINE FString Get()` indexes as
   `FString Get`. False absence on our primary language. Technique: replace macro
   tokens with the **same number of spaces** so byte offsets survive, restore
   `#define` lines verbatim, plus a post-parse `recoverMangledCppName` net (safe by
   construction — only touches names already containing a space that isn't
   `operator`/`~`). Ref: `reference/codegraph/src/extraction/languages/c-cpp.ts:787`.
3. **Out-of-line C++ method qualified names** (S) — *verified gap.* `namespace sim
   { Output MyClass::Apply(){} }` indexes as `MyClass::Apply` while the class node
   is `sim::MyClass`; they never link and callers returns **empty**. We already
   strip template args (`cpp.js:31`); only the namespace-prefix composition is
   missing (`namespace_definition` appears once, at `cpp.js:375`, as a Module node
   and is never composed). Ref: `composeReceiverQualifiedName`
   (`src/extraction/tree-sitter.ts:1435`) — anchor at the first segment the
   receiver already names.
4. **Truncation banner at the TOP with `shown/total` + named escape hatch** (S).
   `mcp/stdio/query/renderer.js:73-82` emits `+N more` at the **bottom only** with
   no total; a bottom marker reads as silence to an agent that stopped reading.
   Every notice must name a specific parameter and a specific alternate tool.
   Caveat: truncate the item list before serializing, never the serialized JSON.
5. **`isError` discipline** (S) — codegraph's repeatedly-observed finding: one or
   two `isError:true` responses early and the agent **stops calling the server for
   the rest of the session**. Reserve it for genuine "stop trying"; return
   recoverable conditions (not indexed, symbol not found, busy) as success-shaped
   responses carrying guidance. `mcp/stdio/server.js:1150` returns `isError:true`
   from a generic catch.
6. **`dump-graph.mjs` equivalence oracle** (S, ~58 lines) — nodes/edges/refs by
   natural key, lexicographically sorted, so any extraction change is gated on a
   byte-identical `diff`. Makes P0-1 and items 2–3 falsifiable instead of vibes.
7. **Interrupted-index truncation marker** (S-M) — no marker today for "an index
   run was killed mid-way", so `exhaustive:true` would be silently wrong. Plus a
   whole-index-frozen tier checked **before** the per-file banner (once watching
   stops, the pending set is empty so the per-file banner can never fire).
8. **Contract-singleton assertion** (S) — assert the
   `evidence.{ready,degraded,cause,exhaustive,confidence}` wording and the
   "absence requires exhaustive:true" rule are byte-identical across every skill
   **and** `server-instructions.js`. Extends `skill-parity.test.js`.
9. **`indirect_call` as a distinct relation** (M) — callbacks/dispatch
   tables/registries in the blast-radius set but **not** the strict call graph:
   recall for `graph_impact`, precision for `graph_callers`.
10. **Config-write safety triad** (S) — "absent" vs "unparseable" must branch
    differently (absent→create, unparseable→**abort**); strip BOM before
    `JSON.parse`; back up before modifying writes. Directly relevant to P1-1.
11. **`name_segment_vocab`** (M) — split identifiers into prose segments at index
    time so "authentication" finds `Guardian`-style names, with an honesty gate
    (re-verify candidates against `nodes`) and rarity/co-occurrence tiers.
12. **`readOnlyHint: true` annotations** (S, ~5 lines) — Cursor's Ask mode
    *refuses* MCP tools lacking it; purely additive.
13. **Windows `/^…/gm` + CRLF** (S) — JS multiline `^` anchors after `\r` too
    (Rust's is `\n`-only). Any such regex over file content behaves differently on
    a CRLF checkout and Linux/macOS CI will never show it. Also assert
    `windowsHide:true` on every spawn (clangd/pyright/tsserver).
14. **Untrusted-project-data framing** (S) — briefs are generated from
    repo-controlled text then read by agents at session start; label README/manifest
    content untrusted so embedded directives aren't obeyed.
15. **A/B harness controls** (S) — `DISALLOW=Agent` on all arms (else the no-tool
    arm spawns subagents and you compare topologies, not retrieval); pin a floor
    model on both arms (a stronger model's tool-use masks salience problems); sum
    per-turn `message.usage`, not `result.usage`.

## What the field test says is genuinely GOOD (do not regress)

Worth stating plainly — the failure is narrow and the rest held up:

- **Trust banners are the best feature.** `graph_callers` correctly labelled
  itself heuristic/tree-sitter; `code_intel_hierarchy` correctly labelled its own
  zero as untrustworthy. The honesty machinery works — it is the **LSP path that
  is supposed to be the backstop** that lied.
- `graph_health` loudly self-reports staleness rather than serving stale data
  silently.
- `graph_trace` function ranges were **compiler-accurate**
  (`build_gravity_motion_intents_impl` 5102–6547).
- `graph_explore` dumps verbatim source — that is what let the subagent *prove*
  incompleteness without knowing the answer.
- Overlay integrity: 14 features, **0 broken anchors** across ~643 changed files.
- Incremental reindex: 107 commits / 643 files in ~30s, 0 dirty, 0 broken anchors.

**The precise shape:** structure and orientation data are trustworthy;
**exhaustiveness claims are not**. The banner hierarchy currently points the agent
at the *worse* answer — the heuristic path admits it is heuristic, while the LSP
path claims exhaustiveness and is wrong.

## Honest scope of the evidence

One symbol, one C++ file, one agent, one probe. It **proves** the
completeness-query defect — one counter-example is enough for a claim of
exhaustiveness. It does **not** test the orientation path (`graph_packet`,
briefs, `graph_tour`) or blast-radius, which are plausibly where most of the value
is and which this result does **not** condemn.

> Not stable for completeness queries — proven.
> Orientation — untested, not exonerated.

**Next test to run:** the orientation path, same protocol (subagents barred from
grep/Read, questions with known ground truth).

## Recommended order

1. **P0-1** (fail-closed exhaustive) — one-line default inversion, largest trust win.
2. **P0-3** (caller line mislabeling) — small, removes an actively misleading output.
3. **P0-4** + **P0-2** (collection staleness and coverage ratio into the response).
4. **P1-1** + **P1-2** (unblock the three hermes teammates; correct the per-machine belief).
5. **P0-5** + **P2-6** (regression gate + equivalence oracle) before touching extraction.
6. **P2-1**, then **P2-3**, then **P2-2** (pointer-not-warning; namespace fix; macro blanking).

Do **not** advertise v0.3.x as "stable for completeness/absence queries" until P0-1
through P0-4 ship and the scored test is re-run green.
