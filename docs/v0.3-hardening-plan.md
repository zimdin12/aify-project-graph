### ⛔ THERE IS NO CLEAN COVERAGE BASELINE (established 2026-07-30)

`lspVerifiedPctOfCalls = 24%` has been carried as "last-measured" for weeks. It is
**not a valid baseline**, and neither is any figure taken before today.

sc-manager asked the right question — *was `af75407` in place when the 24% was
measured?* — and the answer is no. Traced with `git log -S`:

| | |
|---|---|
| `ceb6d97` (2026-05-12) | introduced `declLine.indexOf(leafName)` + `let col = 0` fallback |
| `af75407` (2026-07-30 01:01) | replaced it |

Every coverage figure measured in that ~11-week window was produced by code that
**queried clangd at a position it had not established**, in two distinct ways:
substring matches landing inside a longer identifier (`build` inside `Builder`), and
an unfindable identifier silently falling back to column 0. Both returned truthful
answers about the *wrong symbol*, recorded under the intended symbol's id.

**Worse than "measured before the fix": measured before the INSTRUMENTATION.**
`positionGuesses` did not exist until `af75407`, so contamination in that window was
not merely unmeasured — it was *undetectable*. There is no retained signal that
would let us bound it after the fact.

**Direction of bias is unknown and must not be guessed.** The explosion inflates
reference counts, which would push the verified share up; substring mismatches
attribute references to the wrong symbol, which can push it either way. Nobody has
measured it, so no adjustment is defensible.

**Rule: quote no coverage percentage until a converged collection runs on
≥ `103020f`.** 24% is retired, not carried forward.

**What else rested on those numbers.** The measurement that redirected this whole
effort — *"a complete collection moved verified share only 24% → 26%, therefore
completeness was never the binding constraint"* — used two figures from the same
contaminated window. That conclusion is now **unsupported, not disproven**: both
sides carried the same bias so the delta may survive, but nothing establishes that,
and the reference explosion is large enough to swamp a 2-point difference.

The *priority* it produced (trust and adoption over completeness) still stands — but
on **less** than first claimed here, and the overstatement is worth recording
because it was made while auditing an overstatement.

The first version of this paragraph cited two independent legs: the token economics,
**and** "every field report since found a trust defect rather than a coverage gap."
sc-manager checked his own three reports (false resume promise, absent `resumedFrom`,
reference explosion), confirmed all three *are* trust defects — and then pointed out
that **three reports from one agent, in one day, against one collector are not three
witnesses.** Same instrument, same window, same reporter, and the position bug
produced two of the three. That is this repo's own corroboration rule — *agreement is
not evidence when the routes are the same* — applied to my reasoning rather than the
tool's.

What actually remains:

1. **Token economics** (2026-07-27) — measured, and independent of clangd entirely:
   it counts tokens for a verb call versus the `Read` it displaces. Unaffected by the
   position defect.
2. **A structural argument that needs no measurement:** a map that is complete but
   untrustworthy is unusable, because the reader must verify everything anyway; a map
   that is partial but trustworthy is usable *within its stated bounds*. Coverage
   without trust has no floor to stand on. This is an argument from what the tool is
   for, not from data, so no measurement can contaminate it — and it is why the
   priority survives the retirement of the numbers that first suggested it.

One measured leg and one structural argument. Not three.

sc-manager's formulation of why the 24% survived so long is worth keeping: **a
number marked *stale* survives; a number marked *retired* does not.** He had it
correctly flagged "last-measured, NOT current" — and that carefulness is what
preserved it, because "last-measured" reads as *true but old*, which is a licence to
quote with a caveat. The caveat was the transport, not the safeguard.

### What measurement changed about the P2 borrows

Three of the borrow report's claims did not survive contact with our code, and
measuring first stopped ~3 sizeable pieces of work from being built on them:

- **Macro damage was 1 shape, not 5.** Probed each claim: `FORCEINLINE` name
  mangling, reflection-macro class collapse, and leading attribute macros were
  all **fine** in our extractor. Only `class MACRO Name` broke — and it broke
  totally (class + every member). One structural pass fixes it; nine chained
  passes would have been mostly dead code.
- **`indirect_call` / "address taken" is not usable yet.** The natural signal for
  a non-exhaustive CALLER set is "this symbol is used as a value". Our
  `REFERENCES` edges measure too noisy for that — the top hits are name
  collisions (`file`, `abs`, `trust`), not function-pointer uses. Adding noise to
  the trust surface is worse than silence, so P2-1 was scoped to the outgoing
  direction only.
- **P2-3 is an identity change, not a name fix** (see below).

## 1. The defect, fully traced

The field test: `code_intel_references` on `sample_fluid_drag` returned **3 of 8 real
call sites** while reporting `exhaustive:true, degraded:false, confidence:"high",
warnings:[]`.

Our server instructions tell agents `evidence.exhaustive` is the source of truth and
that `exhaustive:true` licenses "no callers / dead code / safe to delete." **The flag
lied.** That is worse than shipping no tool — grep gets it right in one second, and
sc-manager had already made the identical error by hand ("three call sites" in two
commits; the compiler found eight). The tool would have confirmed the wrong answer.

### The causal chain — every link measured

**[PROVEN] Ground truth.** `sim/terrain/Terrain.cpp` holds 9 occurrences:
1 definition (:796) + 8 call sites (:1715, :3528, :3633, :3776, :5836, :5938, :6142, :6175).

**[PROVEN] Not a preprocessor artifact.** Hypothesis that missed sites were `#ifdef`-guarded:
**checked and rejected.** All 8 are plain runtime `if` statements in one file. clangd
truncated *within a single translation unit*.

**[PROVEN] The queried file is in NO compile database.**

| DB | entries | first-party | toolchain |
|---|---|---|---|
| `build` | 512 | **0** | foreign (WSL) |
| `build-debug` | 486 | **0** | foreign (WSL) |
| `build-linux-mgr` | 511 | **0** | foreign (WSL) |
| `build-win-clang` | 466 | **0** | native |
| `build-win-clangd` | 441 | **0** | native |

`Terrain.cpp` appears in **zero** of the five. Every entry in all five DBs is
`_deps/` third-party (SDL3 etc.) — sand_castle's CMake exports compile commands for
its dependencies but **not for its own engine/sim/game sources**. clangd therefore
has no compile command for any first-party file and falls back to inferred commands,
producing a partial index. That is the 3-of-8.

**[VERIFIED] Why we still claimed exhaustive — `compile-db.js:816`:**

```js
complete: !foreignBlocking && !unityUnexpanded,
```

C++ "coverage complete" means exactly two things: the DB is not foreign, and not an
unexpanded unity build. It never asks *"does this DB contain the file you are asking
about?"* or *"does it cover any first-party code at all?"* A DB with **0% first-party
coverage** is reported as complete coverage.

Note `computeCoverage` (`coverage.js:171`) passes **no `file`** to the C++ path —
unlike `tsCoverage`, which is file-aware and was already hardened for exactly this
class of bug in the 2026-06-12 audit. **C++ never got the same treatment.**

**[VERIFIED] The machinery to detect this already exists and is simply not consulted.**
`prepareCompileDb` already computes and returns `firstPartyCount`
(`compile-db.js:487-497, 711`). The probe uses it to *choose between* DBs
(`:578` "tie-break by coverage") but nothing ever asks *"is the winner good enough?"*
It picked the best of five equally-useless databases.

**[PROVEN] The evidence grant also fails open independently.**
`tests/unit/code-intel/exhaustive-fail-open.test.js` (7 tests, passing) demonstrates
that `buildReferencesEvidence` returns `exhaustive:true, degraded:false,
confidence:"high", warnings:[]` when `coverage` is `undefined`, `null`, or
`{complete: undefined}` — its own source comment at `code_intel_live.js:110` concedes
"coverage may be undefined … **-> treated as trustworthy**". And
`buildDefinitionsEvidence` (`:167`) grants `exhaustive:true` with **no coverage input
at all**.

*Correction to my earlier diagnosis:* the live cpp path does pass a coverage object and
already fails closed on exception (`code_intel_live.js:397`). So the fail-open default
was **not** the sand_castle trigger — the useless-but-"complete" DB was. Both are real;
they are separate bugs and both need fixing.

**[PROVEN] A corroborating signal was measured and discarded.** `graph_health` reported
`refsNotFoundSymbols: 2274` against `refsFoundSymbols: 6643` — **25% of symbols
resolved no references at all** — a loud partial-index signal that never reaches
per-query evidence.

### P0-4 — `graph_callers` mislabels the caller's declaration line as a call site [VERIFIED]
`callers.js:82` writes `source_file: e.from_file, source_line: e.from_line` into fields

starts. Function-granular edges are a documented design choice
(`docs/known-limitations.md`) and are fine; **presenting a declaration line in a field
that reads as a call site is not.** Either render `CALLS (caller declared at file:line)`
or carry the true call-site line.

### P0-5 — Surface code-intel collection staleness in the response [VERIFIED]
Collection was `collectedAt: 2026-06-19` / `indexedCommit: 900915d5` while HEAD was
`f60c658` — **5 weeks, 100+ commits stale** — visible only deep inside `graph_health`.
`graph_index` does not refresh it and does not say so. `lsp-evidence.js:210` already
computes this and appends `— STALE, re-collect` to the **banner text**; it must also
force `exhaustive:false` in the **structured flag**. Banner and flag disagreeing is
precisely what our own instructions warn about — and the flag is the one we told agents
to trust.

A fixture with a known call-site census asserting we never report `exhaustive:true` on
an incomplete set. The scored external test is a better oracle than anything currently

## 5. P2 — borrow backlog (2026-07-26 reference re-pull)

Licenses: understand-anything **MIT**, codegraph **MIT**, graphify **Apache-2.0** — all
borrowable with attribution (`ATTRIBUTION.md` exists). agent-code-intel remains
pattern-only/UNLICENSED. Ordered by how directly each attacks the P0 failure class.

1. **Turn `exhaustive:false` into a pointer, not a warning** (M) — *"the answer to 'how
   does A reach B' when no static path exists IS the dispatch site."* **[VERIFIED]**
   `dynamic-boundaries.js` (165 lines, 7 forms) is imported by exactly **one** verb
   (`trace.js:24`). Wire it into `graph_callers` / `code_intel_references` /
   `graph_consequences` whenever `exhaustive:false`.
2. **C++ macro pre-parse "blanking"** (M) — **[VERIFIED gap: we have none.]**
   `ingest/languages/cpp.js` is 383 lines with zero macro handling. Reflection-macro-heavy
   classes collapse to ERROR nodes (class + bases + members vanish); `FORCEINLINE FString
   Get()` indexes as `FString Get`. Replace macro tokens with the *same number of spaces*
   so byte offsets survive; restore `#define` lines; add a post-parse
   `recoverMangledCppName` net. Ref `reference/codegraph/src/extraction/languages/c-cpp.ts:787`.
3. **Out-of-line C++ method qualified names** — **[PROVEN, but re-estimated S → M/L. Do NOT
   treat as a quick fix.]** Measured by extracting a namespaced header + impl pair:

   | declaration site | emitted qname |
   |---|---|
   | `sim/MyClass.h` — `int Apply(int);` inside `class MyClass` in `namespace sim` | `sim.MyClass.MyClass.Apply` |
   | `sim/MyClass.cpp` — `int MyClass::Apply(int x) {…}` | `MyClass.Apply` |

   They never link, so callers of the declaration miss the definition (and vice
   versa) — real false absence, confirmed.

   **But the cause is not the missing namespace prefix the borrow report described.**
   `generic.js:370` builds `qname = parentClassQname ? \`${parentClassQname}.${name}\`
   : \`${moduleLabel}.${name}\``. An out-of-line definition supplies
   `symbolInfo.parentClassQname` (`MyClass`), which **short-circuits the module
   prefix**; an in-class member has no such value and inherits the module-prefixed
   parent qname. So in-class and out-of-line members are built by **two different
   qname schemes**, and namespaces are not really involved.

   Why this is not small: `qname` feeds `stableId([type, filePath, qname])`, so any
   change alters **node identity across the whole graph** — invalidating existing
   graphs and shifting resolution behaviour. It also cannot be fixed by module-
   prefixing alone, because a header and its `.cpp` in different files yield
   different module labels and still would not match.

   **IMPACT MEASURED 2026-07-26 — worse than a naming nit, and the fix is NOT qname
   surgery.** A header/impl split produces THREE nodes for one method, and the real
   caller binds to none of the real ones:

   | node | qname | callers |
   |---|---|---|
   | `MyClass.cpp:3` (definition) | `MyClass.Apply` | **NONE** |
   | `MyClass.h:4` (declaration) | `sim.MyClass.MyClass.Apply` | **NONE** |
   | `:0` (synthetic external) | `null` | **`run_it`** ← the real caller |

   `graph_callers("Apply")` returns AMBIGUOUS MATCH between two spellings of one
   symbol; disambiguate to either real node and you get **NO CALLERS** while a
   caller exists. (The contract still holds — absence is always hedged as
   non-exhaustive — but the answer is wrong.)

   **Critically: unifying the qnames would NOT merge the nodes.** `stableId` is
   `[type, filePath, qname]`, and the declaration and definition live in different
   files, so they remain distinct nodes regardless. The real fix is in the
   RESOLVER: when several same-label candidates exist, bind the call to the
   definition (or link declaration↔definition) instead of falling through to a
   synthetic external node. That is a resolution-semantics design pass, gated on
   the equivalence oracle (item 4).
4. **`dump-graph.mjs` equivalence oracle** (S, ~58 lines) — natural-key, sorted dump so
   extraction changes are gated on a byte-identical `diff`. Do this *before* items 2–3.
5. **Interrupted-index truncation marker** (S-M) — no marker today for an index run
   killed mid-way, so `exhaustive:true` would be silently wrong. Plus a whole-index-frozen
   tier checked **before** the per-file banner (once watching stops the pending set is
   empty, so the per-file banner can never fire).
6. **Contract-singleton assertion** (S) — assert the `evidence.*` wording and the

## 5b. Borrow candidate — `understory` (evaluated 2026-07-27)

`reference/understory` (Apache-2.0, 0.35 MB, gitignored like the other refs). A
local-first personal-memory server built on the same Karpathy LLM-Wiki idea we
already credit in `ATTRIBUTION.md`. Different domain, so most of it does not

**TAKE — a per-repo SESSION SEED in the MCP `instructions`** (M, highest value).
`packages/server/src/mcp/seed.ts`. Their framing, verbatim from the source:

> *the seed lists concept DESCRIPTIONS per segment — semantic hooks beat
> filenames for igniting the "memory might know this" instinct.*

Their measured failure was that a client model saw only tool NAMES, so it
answered from its own head and never looked — the knowledge was on disk and
invisible. **We have the same shape:** `SERVER_INSTRUCTIONS` is a static string
describing verbs and rules; it says nothing about what THIS repo's graph actually
knows. An agent learns *how* to call us but not *whether we hold anything
relevant. We already have the raw material — archetypes (named subsystem
clusters), `functionality.json` features with descriptions, and the briefs — so
the work is assembling a compact, budget-capped seed at `initialize` and
appending it to the instructions. Their caps are a sane starting point (~3000
chars, ~10 descriptions per segment) as is listing what a subsystem is ABOUT
rather than its filenames.

**NOTE, partially applicable — orphan/broken-link lint** (`packages/core/src/okf/lint.ts`,
46 lines, deterministic, no LLM). We already validate broken anchors
(`validateAnchors`), and `overlayQuality` counts OUTBOUND feature links
(`featuresWithDependsOn`/`RelatedTo`) but never INBOUND — so we cannot see a
feature nothing references. Worth adding only with a caveat: in their domain an
orphan memory is unreachable and therefore bad, whereas a standalone subsystem in
a feature map is often legitimate. Their real gotcha is worth keeping either way:
**exclude auto-generated index files as link sources**, or everything looks
connected and orphan detection is meaningless.

**NOTE — feature-editing rules** for `graph-feature-edit`: *enrich before you
create* (search for the concept a fact belongs to; patch it instead of spawning a
sibling), *link both ways*, and *contradictions must be REWRITTEN, not appended*
(the old fact has to be gone everywhere). We partly do this via diff-and-confirm,
but the rules are not stated.

**SKIP** — the librarian sub-agent (our verbs already are the librarian), the
local-LLM/llama.cpp stack, and personal-memory semantics.

**Verdict:** worth keeping as a small single-idea reference, NOT a peer of

### DASHBOARD — a second idea worth taking (evaluated 2026-07-27)

`reference/understory/packages/web/src/components/GraphView.tsx` (541 lines,
React+SVG). Their graph view itself is ordinary — force layout, type-coloured
nodes — and ours is richer (Map/Tree/Flow/Force/Shader, grouping, trust lens,
file tree, diff overlay). Two things it does that ours does not:

1. **QUERY-TRACE REPLAY — the one to take.** They record every retrieval the agent
   performs and replay it *on the graph*: `traceVisits(trace)` maps each step to a
   node path with a **sequence number** and a **write flag**, then highlights the
   path the agent actually walked. Their stated reason: *"if it's easy to
   visualize, it's easy to debug."*

   Directly relevant to our open problem. This entire session's hard questions
   were behavioural — *does the agent reach for the map at all, does it take a
   sane route, where does it give up and grep?* We currently have no way to see
   that; the token measurement gives cost per call but not substitution rate, and
   a trace overlay is exactly the instrument for the missing half. It would also
   have made several field defects visible on sight: a verb returning zero, a
   route that dead-ends at a dark region, an agent looping on an unreachable
   long-tail verb.

   Cost is mostly plumbing: verbs would need to emit a step record (verb, target,
   result count, ms) into a per-session ring buffer the dashboard can read. No
   graph-schema change.

2. **Orphan marking in the legend** — a node with `links === 0` renders with a red
   outline and gets its own legend row. Trivial, and it makes the inbound-link
   gap noted above visible without a separate report. Same caveat as before: in a
   feature map a standalone subsystem is often legitimate, so mark it, do not
   call it an error.

**Skip:** their ChatPanel/LogView (a librarian-chat UI we have no analogue for),
and the force layout itself.

## 5c. THE TOKEN BUDGET — measured 2026-07-27, and it indicts this session

The product is a MAP FOR AGENTS: it has to be trustworthy **and** cheaper than the
grep/read it replaces. This session pushed hard on the first and never priced the
second. Measured:

| | v0.3.0 | after this session | Δ |
|---|---|---|---|
| `server-instructions` | ~2156 tok | ~2752 tok | **+28%** |
| session seed | — | ~550 tok | new |
| **always-on, every session** | **~2156** | **~3118** | **+45%** |

Plus per-call growth: a `LOCATIONS` note on every `graph_callers`, `SHOWING n of m`
on search, and longer `lsp-partial` banner wordings.

Every addition is honest. None was priced. A map that costs 3.1k tokens before
the agent asks anything has to displace more than 3.1k tokens of grep/read on the
*average* task, not the best one — and we have no current measurement of that.

**The design rule this suggests, to apply before adding any more always-on text:**
*always-on content is only what changes behaviour on EVERY task; everything else
belongs in the response that needs it.* Concretely, the biggest single offender is
the cause vocabulary — ~600 chars enumerating all 9 `evidence.cause` values in the
system prompt, when an agent only needs to know what `cold_index` means at the
moment it RECEIVES `cold_index`. Those definitions belong on the degraded response
(which already carries a `fallback` string), not in every session's preamble.
Moving them is strictly better: cheaper, and the explanation arrives when it is
actionable. Note `tests/unit/query/cause-vocabulary.test.js` currently enforces
documentation *in SERVER_INSTRUCTIONS*, so it must be retargeted in the same
change rather than deleted.

### MEASURED (same day) — the economics are GOOD, and this corrects the alarm above

Per-call cost, measured on this repo (chars/4 proxy, consistent across verbs):

| call | tokens | vs |
|---|---|---|
| `graph_search` | 70 | |
| `graph_whereis` | 73 | |
| `graph_packet(orient)` | 136 | |
| `graph_callers` | 329 | |
| **reading ONE source file instead** | **4557** | (313-line file) |

A verb call is **14–65× cheaper than a single Read**. Against the 3118-token
fixed cost, **the map pays for itself on the first avoided file read**, and the
+962 tokens this session added is roughly one fifth of one Read.

**So the conclusion inverts: token cost is NOT the problem, and trimming the
preamble is the wrong lever.** The binding risk is ADOPTION — if the agent reads
the file anyway, the map is pure overhead; if it makes one substitution, it has
already paid. That makes the session seed (which exists to drive first use)
correct rather than costly, and it argues against shrinking always-on text that
drives usage.

The cause-vocabulary move is still worth doing, but demote it: it is ~150 tokens
of reference material that does not drive usage, and it is better at point-of-use
because it arrives when actionable — not because it is expensive.

**Still genuinely unmeasured:** whether agents actually substitute. Cost per call
is now known; substitution RATE is not, and that is the number that decides
whether any of this pays. That is an agent-behaviour measurement (ab-runner),
not a static one.

**What is NOT measured and should be, before more work either way:** the actual
displacement — tokens/tool-calls to orient via briefs+packet vs grep+read on the
same task. `scripts/ab-runner.mjs` and `bench-*.mjs` exist for this. Per the
codegraph methodology note, sum per-turn assistant `message.usage`; `result.usage`
is last-turn-only and will undercount.

## 6. What is genuinely GOOD — do not regress

The failure is narrow; most of the machinery held up under an adversarial test:

- **Trust banners are the best feature.** `graph_callers` correctly self-labelled
  heuristic/tree-sitter; `code_intel_hierarchy` correctly labelled its own zero as
  untrustworthy. The honesty machinery works — it is the **LSP path meant to be the
  backstop** that lied.
- `graph_health` loudly self-reports staleness instead of silently serving stale data.
- `graph_trace` ranges were **compiler-accurate** (`build_gravity_motion_intents_impl`
  5102–6547).
- `graph_explore` dumps verbatim source — that is what let the subagent *prove*
  incompleteness without knowing the answer.
- Overlay integrity: 14 features, **0 broken anchors** across ~643 changed files.
- Incremental reindex: 107 commits / 643 files in ~30s, 0 dirty.
- Coverage detection **already fails closed on exception** (`code_intel_live.js:397`) and
  the TS path was hardened file-aware in the 2026-06-12 audit — the pattern to copy for
  C++ is in our own codebase.

**Precise shape:** structure and orientation are trustworthy; **exhaustiveness claims
are not.** The banner hierarchy currently points the agent at the *worse* answer — the
heuristic path admits it is heuristic, while the LSP path claims exhaustiveness and is
wrong.
