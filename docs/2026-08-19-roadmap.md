## What decides priority

Four measured constraints, from `docs/2026-08-19-does-this-earn-its-keep.md`. They are not
re-litigated in this document.

1. **Discovery is the unmeasured, unclaimed task class**, and it is the one Steven actually
   hit. Every study putting grep at 100% presupposes the agent knows the symbol.
2. **Adoption is the largest failure mode** — 58% zero tool calls in one study, 64.6% of
   sessions never invoking in production telemetry. Bigger than any retrieval effect.
3. **The foundation is the least honest layer we ship.** 76% of doc→code edges are prose
   collisions.
4. **Do not compete on symbol lookup.** It is at ceiling for grep and the window is closing
   from three directions.

⚠ And Steven's bar, which vetoes: *"without producing specific slop or something that has low
value."* Every phase below has to survive that, and two candidates already died against it.

## Phase 1 — Make the foundation honest

**The problem, measured — and my first statement of it was wrong twice.** ~2,370 `MENTIONS`
edges over 73 documents, **83.5% with an all-lowercase-word target**. ⛔ That is a property of the
ADMISSION RULE, not a correctness label on each edge: a doc can genuinely refer to `read`. What is
established from source is that `mentions.js` admits every regex word collision, takes the first
node for an ambiguous label, and records line 0.
⭐ `ef-manager` ran it on echoes: **63.1%** — twenty points apart, same extractor. The rate tracks
the language's naming convention, so **no global threshold or hand-tuned stop-word list can be
right on both repos.**
⭐ And frequency is inversely correlated with value: the noisiest term has 60 edges, the genuinely
doc-referenced symbols have 9, 7, 5, 4.

**Why first.** Steven: *"file mapping is the basis for the graph, like foundation layer, it has
to be accurate and super good."* A wrong edge here is worse than a missing one, because every
layer above will cite it.

⏳ **Design pending `graph-senior-dev`'s ruling** on: which admission rules are load-bearing
(backtick/code-fence context, qualified names, path co-reference, common-word denylist); and
whether to **delete**, **demote**, or **rank** the 76%. My lean is delete-and-re-derive; I have
asked to be overruled, because this removes data rather than a check.

**Exit criteria — measured, not asserted:**
- A doc→code edge sample (n ≥ 100, seeded, frozen) adjudicated by hand; precision reported with
  the sample, not a claim.
- Every surviving edge carries which rule admitted it.
- Recall reported honestly against the same sample. ⛔ If precision rises and recall is unknown,
  we have not finished, we have moved the defect.
- `ef-manager` reproduces the measurement independently before it is called done.

## Phase 3 — Adoption: stop requiring the agent to remember

**The measured problem.** Agents do not reach for the tool, and they route *correctly* when they
skip it. Skills and descriptions are worth more measured points than index quality.

**3a. Task-shaped skills.** Started: `blast-radius` and `safe-to-delete` shipped in `fc30004`,
borrowed in shape from `cursor/plugins` pstack. Nine of thirteen existing skills operate our tool
rather than doing a job; those need re-pointing or retiring.

**3b. ⭐ Hook-injected pointers — Steven's idea, and the strongest adoption lever we have.**

*Can we do it today?* **Yes.** We already ship a `SessionStart` hook
(`scripts/hooks/session-start-hint.mjs`), Claude Code supports `PostToolUse` on `Edit`/`Write`,
and `graph_explain_diff` already takes `files[]` and returns AFFECTED one-hop callers grouped by
file, plus LAYERS, RISK and TESTS. The pieces exist; none of it is wired.

*Why it beats every other adoption idea:* **a hook does not require the agent to reach.** That is
a direct answer to the 58%/64.6% figures rather than another attempt to persuade.

⛔ **AND IT IS THE HIGHEST SLOP RISK IN THIS DOCUMENT.** Injecting text on every edit is a token
cost on every edit, and our own measured finding is that **behaviour changes only when a field
CONTRADICTS the agent's confidence, never when it merely adds data**. A hook that says "here are
the callers" every time is noise that agents learn to ignore — and a frequent signal later
disproved teaches them to ignore it permanently.

⇒ **The design rule: fire rarely, and only on contradiction.** Candidates worth testing, each of
which tells the agent something it probably believes the opposite of:
- you edited a function with callers **in files you have not opened this session**;
- you changed a signature and callers exist **in TUs the compile DB does not cover**;
- you deleted a symbol that **has callers**;
- you edited a file an open task or feature marks as **owned by another lane**.

*Where it lives.* Steven is separating `aify-wrapper` with a contract, used by `aify-comms` and
the new `aify-dashboard`. Two placements: a Claude Code `PostToolUse` hook (works today, host
specific) or the wrapper (works for every runtime the wrapper covers, needs the contract).
⏳ Placement is Steven's call; the *content* is ours either way, and the content is the hard part.

**Exit criteria:** a measured fire rate and a measured act-on rate. ⛔ If it fires on more than a
small fraction of edits, it is slop by definition and gets cut regardless of how clever it is.

**3c. Cut the surface.** codegraph cut their default listing from 4 verbs to **1**, stating the
reason is not token cost but *"presence itself steers mis-picks"*, and separately measured a
**+546 token** always-paid schema cost. We list 17.
⏳ `ef-manager` has been asked which they actually reach for, which they have never needed, and
which have wasted a call. This is a **listing** decision, not a deletion — everything stays
callable.

## Phase 4 — Finish the refactor, and say what it actually covered

⚠ **It was recorded as complete and was not.** Commit `067e3ad`, titled "TARGET MET", claimed
*"no file over ~710 lines"*. At that commit **fourteen files exceeded it**. The two files it set
out to split were split and still hold (`server.js` 1395→749, `generator.js` 1966→631); the
scoped result was promoted to a global claim in the commit message and then in session memory,
where it sat for a week telling future sessions not to re-audit.

**Current state:** `packet.js` 1453 (larger than `server.js` was before the refactor),
`consequences.js` 1328, `health.js` 1318, `compile-db.js` 1157, `importer.js` 1146,
`pull.js` 1096, and seven more over 710.

**How this one is done differently:**
- The target is stated as a **measured predicate with a denominator**: *"N of M source files
  under 710"*, reported before and after. Not a title.
- One slice per commit, behaviour proven unchanged by a byte-identical output comparison against
  a detached pre-slice worktree — the method that worked last time.
- ⛔ **`packet.js` first**, because it is the largest, it is the most-called verb, and it carries
  the packet-list guarantee that took ten versions to make honest. If slicing it is unsafe, that
  is worth learning on the first slice rather than the last.
- The completion claim names its population or it is not made.

## Phase 5 — The cross-layer edges, which are the actual product

Only after Phase 1. This is the layer Steven describes: *this decision came from that doc, that
decision built this feature, it lives in these files.*

Borrowable, verified by the reference audit:
- **Tier-scoped merge** (graphify `97656fa`): ownership keyed on `(source_file, tier)` so
  re-extracting code cannot delete the overlay. They shipped this after the bug bit them.
- **Content-fingerprinted verdicts** (graphify `reflect`): a stored conclusion carries a hash of
  the code it cited and self-flags *"code changed — re-verify"*. That is our anchor-drift problem
  solved.
- **Warn → persist → retry** (understand-anything `f712244`): dropped edges are recorded and
  re-injected next run rather than lost silently.
- **Deterministic gating** (understory `dream.ts:86-88`): expensive LLM refresh runs only when
  cheap signals say something changed. No signals, no spend.

⚠ **No doc→symbol linking pattern exists to copy.** graphify's markdown extractor *documents*
heading→symbol edges via backticks and **the code does not exist**. This is a place people claim
to have solved and have not.
