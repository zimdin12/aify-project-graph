## Phase 0 — Stop measuring with a broken ruler ✅ DONE (`873afdc`, `14fb8c9`)

Both A/B harnesses read one `turn.completed` out of N. **One-sided**: under-counts whichever arm
took more turns. Every number that harness produced is suspect.

⚠ **And my fix was wrong, which is the part worth keeping.** It called a growing series
"cumulative" and took the last value — inference from shape, inside the instrument built to stop
inference from shape. dev executed it. **Every non-decreasing series is ambiguous from values
alone**; only a decrease proves anything. Usage semantics is a property of the HOST, so an adapter
now DECLARES it, a declaration the data contradicts is refused, and the collector reports its own
coverage instead of silently skipping turns.

⏳ **Remaining:** establish `usageSemantics` per harness. Until then every multi-turn total refuses.
**That is correct and it blocks the efficacy re-run.**

### ⭐ A STRONGER DISCRIMINATOR THAN A PROVIDER TOTAL — `scripts/establish-usage-semantics.mjs`

**A cumulative counter cannot decrease.** So ONE decrease anywhere in the series refutes the
cumulative reading outright — a proof, needing no second source, no window-matching, and with no
ambiguity on a mismatch. Ranked above the provider-total route, which depends on that total covering
exactly this window.

Validated: a real Claude Code session transcript decreases at **6,130 of 23,561** steps.

⛔ **AND THAT VALIDATES THE DISCRIMINATOR, NOT A HOST.** Those numbers come from parsing
`message.usage` directly. `collectTurnUsage` — what the A/B runner actually uses — reads
`turn.completed` and returns **ZERO** usage turns on that same file. Saying "validated on Claude
Code" would be a contract certified by an instrument that cannot read the subject.

⛔ **AND THE HARNESS DRIVES CODEX, NOT CLAUDE.** `runCodexCell` is its only agent adapter. A
contract proven on one host is worth nothing on another; declaring it would be the wrong-host error.

⇒ **SO PHASE 0 IS STILL BLOCKED, BUT ON ONE COMMAND RATHER THAN ON ANALYSIS.** No frozen Codex
transcript exists in the repo. Run one Codex cell, point this at its transcript, and it answers

## Phase 1 — Make the foundation honest

### The measurement, stated the way it survives review

~2,370 doc→code `MENTIONS` edges over 73 documents on APG; **83.5% have an all-lowercase-word
target**.

⛔ **That is a property of the ADMISSION RULE, not a correctness label.** A doc can genuinely
refer to `read`. My first write-up said "76% wrong" and both agents corrected it independently —
wrong number *and* wrong characterisation. What is established from source: `mentions.js` admits
every regex word collision, takes the **first** node for an ambiguous label, and records **line
0**.

⭐ **One repo could not show the shape.** `the field test` ran it on echoes: **63.1%** — twenty points
apart, same extractor. The rate tracks the **language's naming convention**: JavaScript names
functions `exists`, `count`, `list`, `read`, colliding with English head-on; C++ leans CamelCase
and `WorldBuffer` survives contact with prose.
⇒ **No global threshold or hand-tuned stop-word list can be right on both repos.** It must be
derived per-repo from the extracted namespace.

⭐ **The ranking is inverted.** The noisiest term carries 60 edges; the genuinely doc-referenced
symbols — `ensureFresh` 9, `openDb` 7, `clampToBudget` 5, `renderCompact` 4 — carry the fewest.
**Frequency and value are inversely correlated.** "Most-mentioned symbols" is a noise generator;
truncating a mentions list by count drops the signal first.

⚠ `the field test`'s scope, which is the more useful fact: *"it cannot have cost me, because I never
consumed it."* In days of intensive field use the doc layer has had **zero consumers**.

### The ruling: DELETE and rederive

the reviewer's ruling, accepted. Not demote, not rank.
- Confidence is ignored or inconsistently applied by degree/ranking consumers.
- Demoting still asserts a relationship exists when only a token collision does.
- **60 wrong edges to `files` distort community, breadth and document ranking *before* ranking
  runs.** You cannot rank your way out.
- Rejected-candidate diagnostics belong in index **telemetry** (`candidates`,
  `rejected_ambiguous`, `rejected_prose_shape`, `admitted_by_rule`), not in graph edges.
  **Edge count is not capability. Removing false data increases capability.**

⛔ **The migration must be deletion-sensitive.** A rebuild purges all `extractor='mentions'`
edges; an incremental doc reindex deletes that document's prior derived edges before rederiving.
`INSERT OR IGNORE` alone preserves the poison forever.

### The invariant, in the reviewer's words

> **A stored doc→symbol edge must carry a recoverable source span and a deterministic resolution
> path to exactly one code node.**

Build a label → **all candidates** map. **Never repeat today's `if (!symbolMap.has(label)) first
wins`.** An ambiguous label emits no edge unless local evidence disambiguates it.

**Admission rules, strongest first:**

1. **Exact Markdown/path link → an indexed repository file.** Emits a dedicated Document→File
   relation (`LINKS_TO`), **not** a symbol `MENTIONS`. ⭐ Highest-value foundation edge, and the
   one that directly serves "where is the design doc".
2. **Qualified code reference resolving uniquely** — `Ns::Type::method`, `Type.method`,
   `obj->method`. Not "strip to the last word and take the first match".
3. **Invocation/type-shaped token resolving uniquely**, in inline code or a language fence —
   `graphWhereis(...)`, `SomeType`, `snake_case_symbol`.
4. **Path-scoped symbol reference** — an exact file and a symbol declared there **in the same
   local span** (link, sentence, list item, fenced example). Whole-document co-occurrence is too
   weak.

⛔ **Backticks alone are NOT sufficient.** Docs backtick `read`, `file`, `query`, and fences hold
shell, JSON and output.
⛔ **Do not own a stopword dictionary** — dev: *"it will become the next unexplained authority."*
⛔ **A bare prose exact-name collision emits nothing, even for a unique symbol.** Uniqueness says
only one target exists; it does not prove the author referred to it.

**Provenance must reach the reader, not just the database:** real `source_line`, `provenance:
INFERRED` (the occurrence is observed; the identity mapping is inferred), `extractor` naming the
rule, confidence fixed **by rule, never by symbol popularity**.
⚠ `documents_mentioning` currently labels the whole field `observed`. That collapse is wrong and
`tests/unit/query/observed-doc-mentions.test.js` enshrines it — both get rewritten.
⛔ **A mention is not causality.** "This decision came from this doc" is a different relation and
a different authority class. It starts as a **curated** overlay link, never inferred from a
mention.

### Acceptance gate ✅ ANSWERED 2026-08-22 — `c8dcb2e`, `a8edd8b`

Stratified frozen hand-labelled sample, including negative-control docs using the same word in
ordinary prose. **Precision floor ≥0.95 per admission rule, not aggregate.** Recall disclosed as
a floor. **A rule below the floor is deleted, not rescued by ranking.** `the field test` reproduces
independently, on **both** repos, before it is called done.

**Graded blind by `the field test` on three corpora that had never been indexed** — `graphify`
`b14b52e9`, `agent-understand-anything` `32944829`, `codegraph` `c6aaa203` — because the earlier
0.970 came from the corpus rule 4 had been tuned against three times. Prereg + result:
`docs/2026-08-22-prereg-heldout-doc-ref-precision.md`.

| rule | verdict | the claim I am allowed to make |
|---|---|---|
| `doc_ref:shaped` | 311 C / 23 W / 3 U = **0.9311** | ⛔ **DELETED**, per the reviewer's ruling. 98 edges → 35 here. |
| `doc_ref:path-scoped` | **89 / 89**, LB ≈0.959 | *evidence* it clears the floor — not proof |
| `doc_ref:qualified` | **35 / 35**, n=36, LB ≈0.90 | consistent with clearing it; does **not** establish it |

⭐⭐ **The property that separated survivors from casualties:** both surviving rules put a
**structural anchor ADJACENT to the token** — a path in scope, or a `Class.` prefix. Rule 3's only
evidence was ambient prose. That one fact explains both its imprecision (a Go `init()`, a declared
`trace(a,b)` notation and another repo's `forward()` all satisfy "resolves here, uniquely") and its
fragility. **⇒ ADJACENT, NOT AMBIENT** is the requirement for any successor, and it now governs the
Phase 2 work above too.

⚠ **Two apparatus defects, each found from the other side, neither changing a verdict.** Theirs:
462 rows graded through ±85-char windows over an artifact carrying the full line. Mine: the artifact
printed a bare `target_label`, so five sibling `auth_flow` methods were indistinguishable — fixed in
`a8edd8b` with `target_qname`. A regrade of the 125 survivors at full text moved **zero** verdicts,
with 63 of the 125 confirmed truncated, so the null result is measured rather than assumed.

⛔ **STILL OPEN: the sample is SPENT.** Any rule changed in response to it is contaminated by it.
`agent-code-intel` is licence-blocked and nothing else on this machine is untouched, so **the next
honest measurement needs a corpus that does not exist yet.** Recall remains disclosed as a floor and
is not measured — see the refusal:admission ratio argument, unchanged.

## Phase 2 — Discovery: ALIVE, and the target moved

⭐ **The kill-switch did not fire.** I asked `the field test` whether discovery is real or a story
around one anecdote. Their answer is the strongest evidence in this document:

> They hit Steven's failure themselves, twice, and solved it by **hand-building the artifact
> THE-GOAL describes** — `MEMORY.md`, ~120 one-line pointers to documents, maintained by hand
> across compactions, entirely outside our tool, *"because nothing else answers 'what do I know
> that I have forgotten I know'."* And twice this week they needed a specific doc, knew roughly
> what it was about, and got there with `git grep`.

⚠ **Two corrections that change the design:**

1. **Steven's case and `the field test`'s case are different problems.** Steven's agent forgot a doc
   **existed** ("what is here"). `the field test` knows it exists and cannot **locate** it ("where is
   the thing I half-remember"). A design serving only one will feel like a miss to whoever has
   the other. Both are recorded in THE-GOAL now.
2. ⛔ **Our competitor on discovery is not grep — it is `ls docs/`.** It finds what you do not
   know to search for, costs nothing, and needs no index. On 73 docs, `ls docs/ && head -3` is a
   real bar. ⇒ **Aim the eval at *topic* → doc where the filename does not contain the topic.**
   "Can it find game-design.md" is a test `ls` also passes.

Partly shipped (`5a3b3d9`): multi-word tokenization, and `kind:"all"` reserves page space. That
took **three attempts**. `the field test` has two probes designed to find a fourth mistake: a query
whose only hit is a doc whose **filename contains no query word**, and a query with **zero**
legitimate doc answers — *"a reserved slot is a strong incentive to promote something."*

### ✅ BOTH PROBES RUN, 2026-08-22 — full measurement in `docs/2026-08-22-phase2-discovery-surface.md`

**Neither found the fourth mistake.** The reserved slot does not manufacture an answer: `resolve`
returns 22 lines of code hits and promotes **0** documents, while `roadmap` and `efficacy` return
documents — so the slot fires when it should and stays empty when it should not. And probe 1 passes
via TITLE: `roadmap` returns `code-intel-v2-status.md`, whose filename contains no query word.

⛔ **But the measurement found something larger than the probes were aimed at. `nodes_fts` indexes
`label` only.** Search additionally queries `extra.title`. **No document body text is searchable
anywhere in the system.** Ten topic words this repo genuinely discusses:

| overlay | clangd | sqlite | precision | staleness | worktree | mutation | compaction | tokenizer | heartbeat |
|---|---|---|---|---|---|---|---|---|---|
| 95 bodies / **0** names | 68 / 1 | 58 / **0** | 50 / 1 | 31 / **0** | 23 / 1 | 12 / **0** | 4 / **0** | 2 / **0** | 1 / **0** |

⇒ **7 of 10 have ZERO reachable surface** — unreachable *by construction*, not by ranking.
`graph_search("sqlite")` answers NO RESULTS on the repo whose storage layer is SQLite.

⛔ **NOT a 99.4% miss rate, though I computed that first.** Body-word presence is not ground truth
for relevance — returning all 95 `overlay` documents would be catastrophic precision. That is the
legacy-`mentions` error reproduced on the same layer in the same week. The claim is about
**capability, not accuracy**: a topic living only in bodies cannot be reached at all.

### ✅ THE ADMISSION RULE SHIPPED — headings, not full text

Not full-text indexing: same argument as the doc→symbol rules, same requirement — evidence
**adjacent and structural**, never ambient. A heading is a claim the author made about a section;
a mention is a coincidence of vocabulary. Headings admit **14%** of body-presence and take
reachability from **3 → 52** across the ten topics.

⛔ **AND THE MEASUREMENT EXPOSED A SEPARATE, PRE-EXISTING DEFECT that made `kind:"all"` a lie for a
whole class of query.** `graph_search` short-circuits on an exact `label` match. A document is never
reached by label — a label is a filename — so whenever the query was a valid symbol name AND any
node carried it exactly, **the widened query was never executed**:

| query | exact-label nodes | fast path | docs matching by heading | returned |
|---|---|---|---|---|
| `overlay` | 4 | **FIRES** | 24 | **0** |
| `clangd` | 1 | **FIRES** | 13 | **0** |
| `sqlite` | 0 | skipped | 2 | 2 ✔ |
| `staleness` | 0 | skipped | 5 | 5 ✔ |

Perfect discrimination. ⇒ Not ranking and not a cap — **the reserved-page-share machinery sits
downstream of a `return`**, so no amount of tuning it could ever have helped. This predates the
heading index; it blocked TITLE matches the same way, which is why `kind:"all"` appeared to work
only on queries that were not symbol names. Fixed by skipping the fast path when the caller
explicitly widened; the default `kind:"code"` keeps it and is pinned by a control.

⛔ **CORRECTION to the line that was here:** I wrote that `extra.summary` is "truncated at ~100
chars, cut mid-word". It is not truncated at all — `extractDocumentMeta` takes line 2 whole, and the
file is hard-wrapped at ~90 columns so a paragraph's second line simply ends mid-sentence. I
inferred a mechanism from an appearance without reading the producer. The real problem is smaller:
"the second non-blank line of a hard-wrapped file" is a poor summary, and nothing searches it.

## Phase 3 — Adoption

**3a. Task-shaped skills.** `blast-radius` + `safe-to-delete` shipped (`fc30004`). Nine of
thirteen remaining skills operate our tool rather than doing a job. *(Count verified 2026-08-22.)*

### ✅ `find-the-doc` shipped (`6bfa315`) — and building it found the adoption defect

THE-GOAL's named scenario — *"my agent asked me today where the game design doc is"* — had
**no skill routing to the doc layer at all**. The new one leads with the direction that is precise
(code → documents, 89/89 and 35/35 held-out) and states the other direction's floor plainly.

⛔ **AND THE SKILL'S OWN EXAMPLE FAILED WHEN I TESTED IT**, which is how the real defect surfaced.
`graph_pull("mcp/stdio/server.js")` returned **zero** documents while **thirteen** doc edges pointed
at that file. `DEFAULT_LAYERS` did not include `docs`; it was opt-in behind a parameter a caller
must already know exists.

⇒ **That is the whole explanation for "the doc layer has had zero consumers."** We spent weeks
treating it as a PRECISION problem — grading blind on three held-out corpora, deleting a rule at
0.9311. All worth doing, none of it the reason. **The layer was unreachable from the front door.**

⛔ **It was already known, and answered with a POINTER.** A test here reads *"REACHABLE-BY-ARGUMENT
IS NOT REACHABLE"* and the source said *"adding docs to the defaults makes every pull pay for a
layer most callers do not want."* Never measured. Measured now: **194 of 657 files (29.5%)** have
any doc edge, median 1, p90 3 — **empty for 70.5%**. The disclosure sentence cost about the same as
the data and bought a round trip. `docs` is now a default layer.

⇒ ⭐ **The generalisable lesson for the rest of Phase 3: we keep improving the QUALITY of things
nobody can reach.** Before the next quality push, check reachability from the verb an agent
actually calls, with no arguments they would have to already know.

**3b. ⭐ Hook-injected pointers — Steven's idea, and the strongest adoption lever available.**

*Can we do it today?* **Yes.** We ship a `SessionStart` hook, Claude Code supports `PostToolUse`,
and `graph_explain_diff` already takes `files[]` and returns one-hop callers grouped by file plus
LAYERS/RISK/TESTS. Nothing is wired.

*Why it beats the alternatives:* **a hook does not require the agent to reach.** That answers the
58%/64.6% figures directly instead of trying to persuade an agent that is routing correctly.

⛔ **Highest slop risk in this document.** Our own measured finding: behaviour changes only when a
field **CONTRADICTS** the agent's confidence, never when it adds data. "Here are the callers" on
every edit is a per-edit token cost that agents learn to ignore — and a frequent signal later
disproved teaches them to ignore it permanently.

⇒ **Fire rarely, only on contradiction.** Candidates: callers in files you have not opened this
session; a signature change with callers in TUs the compile DB does not cover; deleting a symbol
that has callers; editing a file an open task marks as another lane's.

**Exit criterion: a measured fire rate.** Fire on more than a small fraction of edits and it is
slop by definition, however clever.

### ✅ MEASURED 2026-08-22, before the hook was written — `docs/2026-08-22-hook-fire-rate.md`

Population: last 120 commits, **83 touched a JS source file** — what a `PostToolUse` hook would see.

| candidate | fires on | verdict |

instrument would have killed the viable rule.**

⚠ 4.8% is an UPPER BOUND, not the rate — the real rule also requires the deleted symbol to have
